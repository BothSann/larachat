# larachat — instructions for Claude

Real-time chat. Monorepo: `apps/api` (Laravel JSON API) + `apps/web` (TanStack Start). Read [README.md](README.md) for setup and [docs/plan.md](docs/plan.md) for what to build next.

## 1. This is a learning project — the owner types the code

- The owner types **all app code in both apps**, and runs every generator, install, and migration.
- Claude teaches, reviews, and checks. It does not write app code unless the owner says "you write it", and then only the named scope.
- Backend lessons: use the `/laravel-learn` skill. It follows `learn/learn.config.json`.
- Frontend lessons: use the `/tanstack-learn` skill and [.ai/rules/web-learning.md](.ai/rules/web-learning.md).
- Claude may write docs, rule files, and anything under `learn/`.
- Never touch the owner's `.env`, database, git index, or branch. Give the command instead.

## 3. Fixed decisions (don't re-open without the owner)

- Auth: Sanctum **SPA cookie** auth. Keep the API token-ready, but no tokens in v1.
- IDs: ULID primary keys on `users`, `conversations`, `messages`.
- Database: PostgreSQL. Redis for cache, queue, session, broadcasting.
- Realtime: Reverb + Echo. Broadcasts are queued. Typing uses whispers.
- Web data path: the browser calls Laravel directly through `openapi-fetch`. No `createServerFn` proxies. SSR only for `/` and not-found; `_guest` and `_app` are `ssr: false`.
- Web stack: TanStack Query, TanStack Form + Zod, Vitest + Testing Library + MSW.
- Structure: standard Laravel folders + Action classes. No modules (re-check once there are more than 3 feature areas).
- API docs: Scribe → OpenAPI → `openapi-typescript` types in `apps/web`.
- Versions: latest stable at scaffold time, pinned by lock files. Check `composer show` / `package.json` before relying on an API.

## 5. Style of replies

Plain, short English. One idea or step per reply. Real file paths. Every step ends with a check and its expected output. Never claim a check you didn't run.
