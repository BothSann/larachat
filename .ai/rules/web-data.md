# Web rules: data (apps/web)

General patterns: `tanstack-query-practices`, `tanstack-integration-practices`. This file wins on conflicts.

## API client
- `src/lib/api-client.ts` is the **only** module that talks to Laravel. Built on `openapi-fetch` (`createClient<paths>()`), typed from the generated schema.
- Its middleware adds, on every request:
  - base URL `VITE_API_URL`
  - `credentials: 'include'` (send the session cookie)
  - `Accept: application/json` (JSON errors, never an HTML redirect)
  - `X-XSRF-TOKEN` from the `XSRF-TOKEN` cookie on non-GET requests; if that cookie is missing, call `GET /sanctum/csrf-cookie` first
  - `X-Socket-ID` from Echo once connected (so `toOthers()` skips this tab)
- Non-2xx becomes a thrown `ApiError` with `status`, `message`, `errors` (422 field map), `code`. Query and mutation functions get data or a thrown `ApiError`, never `{ data, error }`.

## Types
- `src/lib/api/schema.d.ts` is generated by `pnpm gen:api` (Scribe OpenAPI → `openapi-typescript`). Never hand-edit it.
- No hand-written copies of API types. Derive with `components['schemas'][...]` or from the client's return types.
- API contract changed → `php artisan scribe:generate` then `pnpm gen:api`, commit both.

## Query wiring
- `src/router.tsx` creates a **new `QueryClient` per call** of the router factory, puts it on the router context, and uses `setupRouterSsrQueryIntegration` from `@tanstack/react-router-ssr-query`.
- Defaults: `staleTime: 30_000`; no retry when the error is an `ApiError` with status 4xx; refetch on window focus stays on.
- All server data goes through Query. No `useEffect` + `fetch`.

## Feature folders
```
src/features/<feature>/
  queries.ts     queryOptions factories (key + queryFn together)
  mutations.ts   useXxx hooks around useMutation
  schemas.ts     Zod schemas (forms, search params)
  components/
```
- Keys start with the feature name: `['me']`, `['conversations', 'list']`, `['conversations', id, 'messages']`.
- Loaders and components use the same `queryOptions` object, so keys can't drift.

## Auth cache
- `meQuery` (`src/features/auth/queries.ts`) = `GET /api/v1/me`. Both route guards read it.
- Login and register: `queryClient.setQueryData(meQuery.queryKey, user)`, then navigate to `redirect` or `/chats`.
- Logout: `POST /auth/logout` → `queryClient.clear()` → navigate to `/login`. The next person on the device sees nothing from the last one.

## Chat data
- Message history uses `useInfiniteQuery` with the API cursor.
- Sending is an optimistic mutation: make a ULID (`ulid` package), add the message as `sending`, then swap in the server copy or mark `failed`.
- Live events update the cache; see [web-realtime.md](web-realtime.md).
